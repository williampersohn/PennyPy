# PennyPy
Command-line expense tracker with monthly budget resets, overspend detection, and input validation.
video demo:  https://youtu.be/P1gR7Kquuvg?si=hUB53ftFMCviqb3a
PennyPy is an interactive expense tracker based on command-line arguments. The project folder includes 5 other files: "project.py", "expenses.txt", "a.txt", "requirements.txt", and finally "test_project.py." Expenses.txt and a.txt are based on File I/O, to ensure the expense "tracker" is indeed measuring the budgets left between each interaction with the program. Prior to when the program is run, expenses.txt should be set to a format in which each line contains a category of expense, a separator colon, and the dollar amount of the budget of the specific category in the same line. These categories include "Taxes", "Rent", "Insurance", "Utilities", "Groceries", "Entertainment", "Clothes", "Miscellaneous", and "Investments." No matter what the user inputs into the command-line argument, if it is the first of the month, the function "monthly" is called. At its most basic level, monthly resets the budget back to the original, and accounts for categories of expenses in which the user went over the budget for that month. The program can be used in any month, and does not specify specific budgets for different months. In monthly, the module "datetime" is used. Datetime is the only outside library installed, and is written in "requirements.txt" as "pip install datetime." The method "date.today()" is stored in the variable "today." A regular expression is then used that stores a boolean value in the variable "release" that accounts for whether "today" is indeed the first of the month, which calls monthly to reset the budgets. Although, the budgets cannot be reset every time the program is run when it is the first day of the month; this would lead to resetting more than once per month. "1" is the standard number written in "a.txt", and is changed to a "2" when monthly is called. Monthly is not allowed to reset the budgets while "2" is written in a.txt to avoid repetition. When monthly is not called (it is no longer the first day of the month), "1" is written in a.txt once again, free for the budgets to be reset when it is again the first day of the month. Monthly also includes an evaluation of the budgets each time the program is reset. It uses another regular expression to test if there is a negative in any of the lines, which would indicate that the user went over his budget in that category. If there is a negative number, monthly prints "You went over your (type) budget by $(number without negative sign) this month." Once the program resets or not, it is time for the program to interact with the command-line arguments that change "expenses.txt." Exceptions are included in this next stage, where the program tries to accept the 2 command-line arguments, and if one of them does not exist, the exception prints "No Change", returns a line, and calls the function "originalbudget." Originalbudget prints the original budget at the start of the month, and is printed for nearly every output. For the function to work properly, the first command-line argument is supposed to be the category that the user wishes to update in his budget, and the second is meant to be the amount he spent, or the amount that reduces the budget. Once this category variable is confirmed to exist, it is stored as a string in the variable "type." Once the amount variable is confirmed to exist, it is stored as a string in the variable "money." If they both exist, the exception is not raised and the two variables are put into the function "work" as its two arguments. The work function first opens "expenses.txt" and each line in expenses.txt is iterated. The work function splits each line in expenses.txt into two variables, with the variable "otype" including the name of the category, and the variable "omoney" including the dollar amount of that category. The "o" in front of these variables signify they are the "original", and are compared with the function work's arguments "type" and "money." The ": " is the indicator that the values to the left and right of the ": " should be separated. During the iteration, the program attempts to match each "otype" in the line to the capitalized "type" brought into the "work" function. If the types are completely identical, the leading " $" is stripped off of the "omoney" variable in the same line to interact with the "money" variable. The new variable without the " $" is represented as "orimoney." The boolean variable "works" is originally set to "False," but whenever there is a match between "otype" and "type," it is set to True. This is important because for the next step in the program to occur, it must ensure that there is indeed a match for the program to replace. If there is no match, a TypeError is raised, which is caught at the bottom of "work" and returns "Typo! Try again." When work was called in the main function, it was called inside a "print" method. Therefore, if there was no match, the program would output the previous "Typo!" string, the original budget, and end the program. If "works" is set to True, a new function is called: "change." Change takes "orimoney," as well as "money." Change manipulates these two variables so that the dollars and cents of money are subtracted of those of orimoney as integers, and confirms there is only two decimal places with the format specifier ":.2f." The new representation of the budget is called "new" and is returned to the "work" function right after " $" is put in front of "new." The change function also catches a "ValueError" exception that is caused by the user not including two decimal places in their command-line argument. They either do not include a decimal, one of the zeros, or either of them. If this occurs, the TypeError catches it, and "Add two decimal places" is printed. The output of the change function is set to the variable "toreplace" back in the "work" function. To not cause an error with "toreplace" not receiving an output of the function, the TypeError also returns "no." If "no" is returned, the system exits, with the "Add two decimal places" printed only. This is the only instance when the "originalbudget" function is not printed. In the final part of the "work" function, "expenses.txt" is again opened and its lines are iterated. If the otype matches the command-line "type", the newly created variable "new" stored in "toreplace" replaces to "omoney" value in "expenses.txt." The program then copies which type was replaced, and prints "Changed (type)" and the new budget. The program finally returns to the main function where the "originalbudget" function is printed.
